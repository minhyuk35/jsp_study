🗄️ 데이터베이스 설계
6개 테이블 · InnoDB · UTF-8mb4

MEMBER (회원)

  • member_id (PK)
  • member_pw (BCrypt)
  • member_name
  • email (UNIQUE)
  • phone / addr
  • grade (NORMAL/ADMIN)

HAT (상품)

  • hat_no (PK, AUTO)
  • hat_name / hat_price
  • hat_category
  • hat_stock
  • hat_desc / hat_image
  • reg_date

CART (장바구니)

  • cart_no (PK, AUTO)
  • member_id (FK)
  • hat_no (FK)
  • cart_qty
  • add_date
  • UNIQUE(member_id, hat_no)

ORDERS (주문)

  • order_no (PK, AUTO)
  • member_id (FK)
  • order_total
  • order_status
  • recv_name / recv_phone
  • recv_addr

ORDER_DETAIL (주문상세)

  • detail_no (PK, AUTO)
  • order_no (FK)
  • hat_no (FK)
  • detail_qty
  • detail_price (주문 시 단가)

BOARD (게시판)

  • board_no (PK, AUTO)
  • member_id (FK)
  • board_title
  • board_content
  • board_type (NORMAL/NOTICE)
  • board_hit / reg_date

🔐 보안 처리
🔑

BCrypt 비밀번호 암호화

jBCrypt 0.4 라이브러리 · Work Factor 10 · 매번 다른 Salt 자동 생성
원문 복원 불가 단방향 해시 → DB 유출 시에도 비밀번호 안전

🛡️

SecurityFilter — 인증 · 권한 제어

로그인 필요 페이지 (장바구니, 주문, 마이페이지) 비로그인 시 로그인 페이지로 리다이렉트
관리자 페이지 (/admin/*) ADMIN 등급이 아닌 경우 403 Forbidden 반환

✏️

XSS / SQL Injection 방지

PreparedStatement 사용으로 SQL Injection 원천 차단
HtmlUtils 클래스로 출력 시 HTML 이스케이프 처리 (< > & 등)

🌐

EncodingFilter — 문자 인코딩

모든 요청/응답에 UTF-8 인코딩 강제 적용
한글 입력/출력 깨짐 방지 · Content-Type charset 통일

✅ 결론 & 느낀 점

💡 배운 점

  • MVC 패턴의 역할 분리 중요성 체감Controller ↔ DAO ↔ JSP 명확한 책임 분리
  • DB 설계가 전체 구조를 결정함FK / UNIQUE / INDEX 설계의 중요성
  • 보안은 처음부터 설계해야 함BCrypt, PreparedStatement, Filter
  • 세션과 필터를 통한 권한 관리ADMIN / NORMAL 등급 분기 처리

🔧 개선 가능 사항

  • 실제 결제 시스템 연동PG사 API 통합 (포트원 등)
  • 이미지 파일 직접 업로드현재는 URL 입력 방식
  • Spring Boot로 리팩토링의존성 주입, JPA 적용
  • 검색 기능 추가상품명 키워드 검색

JSP/Servlet 기반의 풀스택 쇼핑몰을 처음부터 끝까지 직접 구현하면서
웹 애플리케이션의 전체 동작 흐름을 깊이 이해하는 계기가 되었습니다.
